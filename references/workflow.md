# 资产与编辑约定

## 一个项目的工作文件

- `work/poster.html`：当前源稿。文案和布局以它为准。
- `work/assets/`：Logo、原始照片、二维码、主视觉、产品图。保留原图。
- `work/assets.json`：资产来源与人物映射，辅助定向修改，不是渲染器输入。
- `work/pages.json`：基于稳定选择器的分页方案，默认与长图源稿同源。
- `outputs/海报-v2/`：本轮通过验证的成品。

映射示例（这是格式说明，不包含真实活动数据）：

```json
{
  "logoLight": "assets/logo-white.png",
  "hero": "assets/hero.png",
  "people": [{
    "id": "person-a",
    "name": "使用文案中的真实姓名",
    "role": "文案中给出的身份，如主讲、嘉宾、创始人、主理人",
    "photo": "assets/person-a.png",
    "confirmedByUser": true,
    "cssCrop": {"objectFit": "contain", "objectPosition": "center bottom"}
  }],
  "qrCodes": [{"id": "contact", "label": "文案中给出的二维码用途", "file": "assets/contact.png"}]
}
```

照片建议在有固定高度的容器内用 CSS 显示。透明人物可根据 alpha 边界调整留白；不要切掉头顶或为了统一比例拉伸脸部。有底色的照片可保留原背景，或在用户要求抠图时调用合适图像编辑工具。产品图、场地图同样按纵横比缩放，不拉伸。Logo 按纵横比缩放，二维码四周保留白色静区。

定向修改示例：选择 `[data-person="person-a"] img` 更新 `src`，并调整该容器的 CSS。不要靠"第三个人物卡片"定位，增加人物后会错位。若用户改名，同步标题、人物卡片、资产映射和正文里的对应提及；不替换无关人物。

## 内容压缩

长文可压缩为主张、要点、人物、收获、适合人群、行动信息。不同活动的"要点"不同：课程是主题与议程，发布会是产品亮点，促销是权益与价格，招募是岗位与要求，展览是展区与时间安排——按文案实际给出的内容命名区块。信息较少就减少段落，不补虚构履历、客户名单、效果承诺或评价。原稿内部称谓不一致时，优先用户当前确认；有实质冲突则询问。

长图转组图优先重排同源内容；轻量活动常见为 4 到 5 页：封面、概览、要点、人物或权益、行动信息。信息较多时继续拆分要点、人物或收获。不同活动不必采用固定页数；没有人物的活动直接跳过人物页。

## 单页海报

单页海报是固定尺寸的一张图：源稿 `#poster` 直接写成目标宽高（如 1080×1440、1242×1660、1080×1920），不使用分页方案，导出时用 `--width` 声明宽度。内容按一屏组织，行动区（二维码、价格、截止时间）放在下半部分。需要同一活动的长图与单页时，两者用同一套文案和素材，单页源稿从长图源稿裁剪而来。
